# Troubleshooting

## Account stuck on "Needs reconnection"

The refresh token is invalid or revoked. In the dashboard, open **Connections** → **Accounts** and reconnect that mailbox.

In **advanced** dashboard mode, you may see `lastAuthError` (for example `Token refresh failed (401 invalid_grant)`). That is Conflu's summary — not the raw provider response.

After reconnect, run the same tool again with the same `account_id`.

## Lost MCP API key

Conflu only shows the full key once at mint time. If you lost it:

1. Go to **Connections** → **MCP setup**.
2. Click **Reveal** to read it again, or **Rotate key** to replace it — rotating revokes the old key immediately, so update every AI client afterwards.

You cannot recover the old key.

## `QUOTA_EXCEEDED_REQUESTS` or `QUOTA_EXCEEDED_EGRESS`

You hit your monthly cap. Check **Usage** in the dashboard. Limits reset at **00:00 UTC on the 1st** of each month; until then, upgrading your plan is the way to get more capacity.

Remember: `account_id: "all"` still counts as **one** request.

## `ACCOUNT_DISCONNECTED`

The tool tried to use an account that is disconnected. Reconnect in the dashboard or pass a different `account_id`.

On list tools with `account_id: "all"`, disconnected accounts appear in the `errors` array instead of being queried silently.

## `UNAUTHORIZED`

Your MCP `Authorization` header is missing or wrong. Use `Bearer cfx_YOUR_KEY` on every POST to `https://mcp.conflu.xyz/v1`.

## `INSUFFICIENT_SCOPES` or `PROVIDER_ERROR`

The provider rejected the call (often 403). Reconnect and accept the requested scopes, or check that the mailbox still has access in Microsoft 365 / Google Admin.

## Reading the request log

Enable **advanced** mode on the dashboard. Open **Usage** → request log table.

Each row shows time, tool, account (email looked up from your account list), latency, status, and Conflu `errorCode` when the call failed. Use it to see whether failures are quota, auth, or provider-side.

## Platform outages

If [conflu.xyz/status](https://conflu.xyz/status) shows a connector degraded or down, the issue is on Conflu's side — reconnecting your mailbox will not help. The dashboard overview also warns when platform checks fail.

## A file tool says `INSUFFICIENT_SCOPES`

File access was added after your account was connected, and an OAuth grant cannot
gain permissions on its own. Reconnect that account from **Connections → Accounts**:
the consent screen will now ask for read access to your files. Nothing else about the
account changes — same record, same id, same history.

With `account_id: "all"`, accounts that still lack the scope come back in `errors[]`
while the others return their files, so one unreconnected mailbox never hides the rest.

## A file came back shorter than it is

Look at `truncated` and `total_bytes` in the response. Conflu reads at most your
plan's per-file cap — 10 MB on Pro, 50 MB on Ultra — and tells you when it stopped
early rather than pretending the fragment is the whole file. For a large document,
open `web_url` at the provider.

Free plans get file listings but no file content: `read_file` returns
`PLAN_UPGRADE_REQUIRED`.
